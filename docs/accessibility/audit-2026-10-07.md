# Accessibility audit, 7 October 2026 (WCAG 2.2 AA)

SEC-06 ([MAT-116](https://linear.app/materia-web/issue/MAT-116)). This report covers the automated audit, the scripted keyboard, structure, reflow, motion, contrast, authentication, live-region, dragging and help checks, and the fixes. The manual screen reader pass (VoiceOver on macOS and iOS, NVDA on Windows) is SEC-06a; its checklist is [below](#screen-reader-checklist-sec-06a). The public statement is [accessibility-statement.md](../compliance/accessibility-statement.md), published at `/legal/accessibility`.

**Result.** No automated violations of any impact on any route, in either theme, on desktop or at phone size. Every scripted check passes. Every critical and serious finding (eleven) is fixed and retested (one by inspection, A11Y-15), and so are the moderate ones (three). Two findings are left as follow-up tickets (one moderate, one minor), and the brand-blue contrast exception is documented in the statement.

## Method

1. **Automated (axe).** `apps/web-e2e/src/a11y-audit.spec.ts` (tagged `@audit`) signs in to a fictional practice with every feature flag on and enough records that pages show content rather than empty states (`apps/web-e2e/src/support/audit.ts`). It visits every route in `app.routes.ts`, every matter tab, the settings pages as an owner and as a read-only member, the signed-out pages, and the dialogs, menus and panels of the key flows. Each page is scanned with axe using the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`, in the light theme and then the dark theme. The theme is switched through `prefers-color-scheme`, which the app follows live, so both scans see the same data. A phone pass uses Playwright's iPhone 13 profile. Scans run with reduced motion emulated, so nothing is measured mid-animation. The ticket's gate is zero critical or serious violations; the specs are stricter and fail on any violation, listing every one a test found across its pages.
2. **Scripted manual checks.** `apps/web-e2e/src/a11y.spec.ts` turns the manual checks into tests that run on every PR: keyboard-only walks with a focus-visibility and obscured-focus check at every stop, the same walk in forced colours, focus trapping in a dialog, landmarks and headings, reflow at 320 px and 640 px, reduced motion, paste and autocomplete on the sign-in and two-step fields, live regions for toasts and Clerk, the dragging alternatives, consistent help, and TabBar target sizes.
3. **Exploration.** A one-off script walked 20 signed-in pages and the signed-out pages with axe's `best-practice` rules, a 45-stop Tab walk, a heading and landmark outline and a reflow measurement at 640 px and 320 px. Its findings are in the table below; the checks that found something are now in the two specs.
4. **Contrast** is checked by axe on every scan (text), and computed from the design tokens for non-text contrast (focus ring) and the documented brand exception.
5. **Screen readers.** What can be checked in code is: accessible names, roles and states (axe), live-region attributes and the text they receive (a11y.spec.ts), and the reading order through headings and landmarks. Hearing it is SEC-06a.

All data is fictional.

## Proposed follow-up tickets

1. **One `h1` on Contacts with a contact open.** Give `mt-person-header` a heading-level input and use `h2` in the Contacts split view (update `contacts.spec.ts`'s level-1 expectations).
2. **A text layer for the PDF preview.** Render pdf.js's text layer under each page canvas so screen readers (and find-in-page) read the text; scanned pages show the OCR text that ingestion already stores.
3. **Run the phone audit in WebKit on PRs that touch `MOB-*` screens.** The morning run covers it; the PR run is Chromium only.
4. **No small white text on brand-500 in the design system.** Switch `mt-count[data-tone="brand"]` and the `mt-court` hearing date to `--bg-brand-hover` in `design/system` (both unused in the app today), so the exception can't creep back.
5. **Undefined design tokens.** Some component styles name tokens that don't exist, so they fall back to nothing (transparent) or to a light-theme colour: `--bg-subtle` (the timer widget, timer dialogs, quick time entry), `--surface-sunken` and `--surface-2` (debtors, template fields), `--text-1`. Map each to a real token and add a check that styles only use defined tokens; A11Y-14 and A11Y-15 were this bug.

## Screen reader checklist (SEC-06a)

Do each flow with each screen reader. Record pass or fail per line with the screen reader and browser versions, and file anything that fails as a bug linked to SEC-06a. Use a fictional practice (the e2e seed, or `pnpm materia-scripts seed` on dev).

Set-up:

- **VoiceOver, macOS:** Safari, latest macOS. VoiceOver on with ⌘F5. VO = Control+Option. Rotor: VO+U. Turn on "Speak hints". Also do one pass in Chrome.
- **VoiceOver, iOS:** Safari on an iPhone, latest iOS. Settings → Accessibility → VoiceOver. Swipe right and left to move, double-tap to activate, rotor with a two-finger twist.
- **NVDA, Windows:** latest NVDA with Chrome and with Firefox. Browse mode by default; Insert+Space toggles focus mode. Elements list: Insert+F7. Also do the keyboard pass once with a Windows contrast theme on (Settings → Accessibility → Contrast themes).

For every page, check that:

- The page title is announced on navigation ("Today · Materia", and so on), and the breadcrumb is read as a navigation.
- The headings list (rotor or Insert+F7) has one level 1 heading, the page name, and the sections below it in order.
- The landmarks list has the "Main" navigation, the main content and, when open, the Clerk complementary region.
- Every control has a name that matches its visible label (2.5.3), its role, and its state (expanded, selected, checked, pressed, disabled, current page).
- Where an empty state is the page's heading (an expired export link, a failed integration callback), it's announced as a level 1 heading. These are `h3` elements with `aria-level="1"`; browsers expose level 1, but check each screen reader agrees.
- A long dialog with nothing to fill in (the keyboard shortcuts, `?`) can be scrolled: Tab reaches its body, announced as a region with the dialog's title, and the arrow keys scroll it.

### 1. Sign in and two-step code

1. On `/auth/sign-in`, the heading and "Work email" field are announced; the field says it's an email field and required.
2. Enter a wrong email format and continue: the error is announced at once and is tied to the field (it's read again when you return to the field).
3. On the password step, the password manager offers to fill (macOS: the key icon; iOS: the QuickType bar). Paste a password: it's accepted.
4. A wrong password: the alert is announced once.
5. On the two-step code page, iOS offers the code from Messages, and macOS from Messages or Mail. Paste "123 456": accepted.
6. Switch to a recovery code and back: focus lands in the new field, and the change is announced.

### 2. Today

1. After sign-in, focus is at the top of the page, and the first Tab is "Skip to content"; activating it moves into the main content.
2. Each section (brief, attention, tasks, deadlines) is a region you can jump to by its heading, and counts are read with their label (not a bare number).
3. Mark a task done from Today: the checkbox state changes, and the "Task done" toast is announced once, politely, without moving focus. Its Undo is reachable with F6 (the notifications region) and works.
4. Mobile (iOS): the TabBar is read as a tab bar or navigation with five items, the current one marked as selected or current. Record is announced as "Record".

### 3. Open a matter: tabs, key facts, parties

1. From Matters, open a matter: the matter's title is the level 1 heading.
2. The matter sections are read as a navigation of links with the current one marked "current page"; moving between tabs announces the new page.
3. Key facts: each fact is read as a label and value pair (a description list), and an empty fact says it's not set. Editing one: the field is announced with its label, and saving is announced.
4. Parties: each party is read with name and role. Adding one: the dialog's title is read first, focus is inside it, and Escape closes it and returns focus to "Add party".
5. Start timer in the header: the button's pressed or running state is announced, and the timer in the top bar reads as the matter number and a time, not ticking every second.

### 4. Create a matter (intake)

1. `/matters/new`: the steps are read as a list with the current step marked; the type cards are radio buttons with their names.
2. On the clients step, "New client…" opens a dialog; Escape closes only the dialog (not the intake), and focus returns to "New client…".
3. Validation errors are announced and focus moves to the first field with an error.
4. Creating the matter announces success, and the new matter's page heading is read.

### 5. Add tasks and deadlines

1. Add task: focus moves to the "New task" field; Enter adds it and keeps focus there for the next one.
2. Open a task's details: "Move up" and "Move down" are announced with the task's title; after moving, focus stays on the button and the new position is announced.
3. A task's checkbox announces "Done: <title>" and its state.
4. Add deadline: the dialog's title and fields are read, the date picker is usable by keyboard and by swiping (iOS), and the created deadline is announced.
5. Deadlines calendar view: each day cell is read with its date and its deadlines; today's date is identified as today.

### 6. Upload and preview a document

1. "Upload" opens the file picker. While uploading, progress is announced at sensible steps (not every percent), and "Ready" is announced at the end.
2. The documents table is read as a table with column headers; sorting announces the sort order.
3. Open a document: the preview toolbar's page buttons are read with names; each page has a "Page n" heading. Confirm the known limitation (the page text isn't read) and that Download is reachable.

### 7. Log time and the timer

1. Press T: the "Log time" dialog opens with focus in the first field; the duration field accepts typed and pasted values.
2. Saving announces the toast once; the dialog closes and focus returns to where it was.
3. The running timer: stopping it from the top bar announces the logged time.

### 8. Clerk chat with citations and suggestions

1. ⌘J (Ctrl+J on Windows) opens the Clerk panel: it's announced as the "Clerk" complementary region, and focus is in "Ask Clerk".
2. Ask a question. **While the answer streams, the screen reader must not read it word by word.** When it finishes, it says "Clerk answered:" followed by the answer, once.
3. Press Stop during an answer: "Clerk stopped. This answer is incomplete." is announced once.
4. Move into the conversation (VO arrows, or NVDA browse mode): each message is an article named "You" or "Clerk", and Clerk's answer is marked as from Clerk.
5. Citations: each is a button or link whose name says what it cites (document and page); activating one opens the source and focus moves there.
6. Suggestions: each is named "Clerk suggestion: <title>", with Accept, Edit and Dismiss buttons; accepting announces the result.
7. The "How Clerk works" link is at the foot of the panel.

### 9. Inbox

1. The Inbox lists notifications by day under headings; each item reads its title, time and whether it's unread.
2. Marking read or done announces the change without moving focus unexpectedly; an empty Inbox reads its empty-state heading.
3. The bell (desktop) announces the unread count, and its popover is navigable and closes with Escape back to the bell.

### 10. Settings

1. The settings navigation is read as a navigation with the current page marked.
2. Profile: "Add photo" opens the file picker; name fields have labels and autocomplete; saving is announced.
3. Team (owner): inviting someone announces success; a role menu reads its options and the selected one.
4. A read-only member hears controls they can't use as unavailable, or doesn't find them, never as working buttons that fail.

### 11. Mobile: Today and Record (iOS VoiceOver)

1. Today at phone size reads in a sensible order: the top bar, the page, then the TabBar.
2. Every TabBar item can be reached by swiping, and the "Record" button is announced.
3. Until MOB-03, Record opens Time and billing: its heading is announced, and "Record time" opens a sheet or dialog whose title is read first.
4. Rotate to landscape: content reflows and nothing is lost.

## How to rerun

```sh
pnpm nx build web --configuration=e2e && pnpm nx build functions
pnpm -s materia-scripts csp emulator-config --out firebase.e2e.json
BASE_URL=http://127.0.0.1:5000 pnpm exec firebase emulators:exec --only auth,firestore,functions,storage,hosting \
  --project demo-materia --config firebase.e2e.json \
  "pnpm exec playwright test -c apps/web-e2e/playwright.config.mts --project=chromium a11y"
```

`a11y.spec.ts` (the PR checks) takes about 1.5 minutes of test time. `a11y-audit.spec.ts` took 7 to 9 minutes of test time across the runs here (4.6 minutes of wall time for both files on two workers): more than the 4 minutes a PR check should add. So it is tagged `@audit` and PRs skip it (`--grep-invert @audit` in the e2e job); the morning run and manual dispatches run it, in Chromium and (the phone pass) WebKit. To run only the audit: add `--grep @audit`.
